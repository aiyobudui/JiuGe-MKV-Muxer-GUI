## 代码审查：九歌批量 MKV 混流工具（jiuge-mkv-gui）

- 未发现致命崩溃/数据丢失 BUG。结构清晰、注释充分，v1.4.1 已修一批真实 BUG。
- 主要问题：
  1. 【高危】`MuxSetting.process_single_task` 先读 stdout 到 EOF 再读 stderr，mkvmerge 在 stderr 超 64KB 时可死锁导致整批卡死。建议并发排空 stderr 或 communicate()。
  2. 【中危】轨道信息后台未加载完就开混流，会静默丢失轨道选择（VIDEO_OLD_TRACKS_* 仍为空）。
  3. 【中危】视频切割同一时间段套用到所有视频，不校验各自时长。
  4. 低危：同目录输出 `_1` 命名冲突、视频格式提示文案与 PreDefined 不一致。
  5. 死代码：VideoCutDialog / get_keep_times / MediaInfoDialog 未被引用。
- 报告已生成：项目根目录 BUG_REVIEW_2026-07-28.md

## 进程残留与启动慢诊断（用户问"进程死缓存 / 双击很慢"）
- 构建形态：build.bat 用 PyInstaller `--windowed` 且**无 --onefile**，即 one-dir 构建；dist 目录约 136MB。所以启动慢**不是**解压到临时目录(_MEIPASS)那种卡顿。
- 不会留"缓存文件"：grep 确认代码无 tempfile.mkdtemp/临时目录创建；切割分片在输出目录用完即删。
- 正常退出干净：`main.run_application()` 在 `app.exec()` 返回后调用 `kill_all_children()`（psutil 递归终止所有子进程），mkvmerge 子进程均被杀。
- **真实残留进程隐患**：① 强制关闭(任务管理器结束任务/崩溃/断电)时 `kill_all_children` 不执行 → 孤儿 mkvmerge.exe 继续跑并锁输出文件；② build.bat 第1步 `taskkill /f /im "JiuGe MKV Muxer GUI.exe"` 只杀主程序、**不杀其 mkvmerge 子进程**，重打包前若正在混流会残留。
- 无单实例锁（无 QLockFile/mutex）：多次双击会开多实例，各自加载+各自触杀软扫描，重复点击会叠加变慢（很可能是用户体感"很慢"的放大器）。
- 双击慢主因：Windows Defender 等杀软对 136MB one-dir 包内每个 DLL 实时扫描（首次/信任缓存失效时最慢，之后变快）；QtMultimedia 预览播放器(QMediaPlayer/QVideoWidget)确被使用，隐藏导入不能删；`--collect-submodules packages` 略增体积但非主因。
- 已实现（用户确认"全部做掉，只能开一个"）：
  1. build.bat 第1步补 `taskkill /f /im mkvmerge.exe`（杀主程序后清孤儿子进程）。
  2. main.py 单实例锁：纯标准库实现（%TEMP%/JiuGeMkvMuxerGUI.lock + 写 PID；O_EXCL 原子创建；启动检测旧 PID 是否存活，存活则弹原生 MessageBox 并退出，死亡则视为陈旧锁接管）。ensure_single_instance() 放在 __main__ 最前、且把 MainWindow/QtWidgets 改为惰性导入，使重复双击在加载 GUI 前就退出。已独立验证 A~D 四场景。
  3. 进程清理兜底：atexit.register(kill_all_children) 与 _release_lock；logger_exception 也先 kill_all_children；正常退出仍保留 run_application 内显式调用。覆盖崩溃/未捕获异常/异常退出。
- 验证：main.py py_compile 通过；单实例锁逻辑独立冒烟测试通过（无 Qt 依赖）。GUI 模块依赖 PySide6 本沙箱未装，需本机最终确认。
